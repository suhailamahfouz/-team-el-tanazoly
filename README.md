# تيم النزلاوي 👑 — Team El-Nazlawy
منصة حجز وتجديد باقات الاتصالات (Angular 18 + Node/Express + MongoDB + WhatsApp Click-to-Chat يدوي).

## التشغيل السريع
```bash
# 1) Backend
cd backend && cp .env.example .env      # املأ JWT_SECRET و ADMIN_EMAIL و ADMIN_PASSWORD (10+ حروف)
npm install && npm run seed && npm run dev      # http://localhost:4000

# 2) Frontend (تطوير مع proxy للـ API)
cd frontend && npm install && npm start        # http://localhost:4200
# لوحة الإدارة: /admin/login

# 3) إنتاج بعملية واحدة
cd frontend && npx ng build
# في backend/.env: FRONTEND_DIST=../frontend/dist/frontend/browser  ثم: NODE_ENV=production npm start
```
يتطلب MongoDB 6+ و Node 20.9+ (يُنصح بـ Node 22 على Render).

## الاختبارات
`cd backend && npm test` — اختبارات API والإيصالات على MongoDB محلي مؤقت ومعزول، تشمل إدارة الحجوزات والتحويلات وسجل WhatsApp اليدوي.

`cd backend && npm run test:gridfs` — اختبارات الإيصالات باستخدام MongoDB محلي مؤقت ومعزول؛ لا تستخدم قاعدة بيانات التطبيق. قد يتطلب أول تشغيل تنزيل ملف MongoDB للاختبار والوصول إلى الإنترنت.

## تخزين الإيصالات ونشر Render

- الإيصالات الجديدة تُحفظ داخل MongoDB GridFS في bucket باسم `receipts` باستخدام اتصال `MONGODB_URI` نفسه. يجب أن يسمح مستخدم قاعدة البيانات بقراءة وكتابة وإنشاء فهارس مجموعات `receipts.files` و`receipts.chunks` و`receipt_uploads`، إلى جانب صلاحيات التطبيق المعتادة. أدرج هذه المجموعات في النسخ الاحتياطية، واستخدم اتصال TLS وقاعدة بيانات دائمة. لا تُعرَض الملفات عبر مسارات عامة؛ الوصول من مسارات الإدارة المحمية فقط.
- ثبّت اعتمادات الإنتاج من `backend/package-lock.json` باستخدام `npm ci --omit=dev`، واستخدم Node 20.9 أو أحدث (Node 22 موصى به)، ثم أعد نشر الخدمة. يتطلب `sharp` ملفًا ثنائيًا مناسبًا لنظام التشغيل أثناء البناء. تحفظ الصور دون تغيير أبعادها؛ PNG وWebP دون فقد، وJPEG بجودة عالية، ولا يُستخدم الناتج إلا إذا كان أصغر من الملف الأصلي. الحد الأقصى للملف 5MB.
- الإيصالات القديمة على القرص تظل قابلة للقراءة إذا كانت ملفاتها المحلية ما زالت موجودة في `UPLOAD_DIR/receipts`. لا تُنقل تلقائيًا، ولا يمكن استرجاع ملف فقدته بيئة Render المؤقتة من قاعدة البيانات. ترحيل الملفات القديمة الموجودة يتطلب نسخها من المكان الذي ما زالت محفوظة فيه، وخطة منفصلة وموافقة قبل تعديل سجلات الإنتاج. صور الشعارات العامة تظل على نظام الملفات المحلي كما كانت؛ هذا التغيير للإيصالات فقط.
- في حال توقف العملية أثناء الرفع، تُترك علامة مؤقتة لمراجعة الملفات غير المرتبطة. `npm run receipts:cleanup` يعرض عدد الملفات المرشحة فقط. بعد مراجعة النسخة الاحتياطية والموافقة، يمكن تشغيل `npm run receipts:cleanup -- --execute` لتنظيف العلامات والإيصالات غير المرتبطة الأقدم من 24 ساعة؛ لا يحذف الملفات المرتبطة بمدفوعات أو تحويلات. لا يُشغَّل التنظيف تلقائيًا.

## شاشة بدء التشغيل

تتحقق الواجهة من `/api/health`، وتعرض شاشة الانتظار عند بطء الاستجابة، ثم تسمح بفتح الموقع بعد 90 ثانية كحد أقصى وتعيد المحاولة في الخلفية. لو الواجهة مستضافة كـ Static Site منفصل، يجب توجيه `/api/*` إلى خدمة الباك اند قبل قاعدة إعادة كتابة صفحات Angular. إذا كانت الواجهة والباك اند يُقدَّمان من نفس خدمة Render النائمة، فلا يمكن لشاشة Angular الظهور قبل أن تستجيب الخدمة الأولية وترسل ملفات الواجهة.

## دورة الحجز
`pending / payment_review → payment_confirmed → processing → activated` (أو `rejected` / `cancelled`).
- الانتقالات مقيّدة وذرّية (لا تفعيل مرتين، ولا تفعيل قبل تأكيد الدفع).
- التفعيل وتأكيد الدفع والرفض إجراءات يدوية من الأدمن فقط.
- واتساب Click-to-Chat يدوي فقط؛ لا WhatsApp API ولا رسائل آلية. فتح المحادثة لا يُسجل كإرسال إلا بعد تأكيد الأدمن يدويًا.
- سعر واسم الباقة يُحفظان داخل الحجز وقت الطلب.

## الأمان (ملخص)
bcrypt · JWT (8h) مع التحقق من الدور من قاعدة البيانات · RBAC (admin / staff) · zod validation · Helmet · CORS محدد · Rate limiting (دخول/حجز/تتبع) ·
الإيصالات تُفحص بالتوقيع ونوع الملف والحجم، وتُخزّن في GridFS خارج المسار العام ولا تُعرض إلا للإدارة المصرّح لها · التتبع يتطلب رقم الطلب + الموبايل.
